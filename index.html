Features

What you get, in plain terms

Drag-and-drop scheduling

Move a story to another day and its publish date follows. Published posts are protected from accidental moves.

Unscheduled panel

Drafts without a date wait in a side panel, so the calendar shows only what is really planned.

Calendar subscription

A signed iCal feed for Apple Calendar or Google Calendar. It is off until you turn it on.

Role-based rules

Writers move work forward, editors and administrators decide what publishes, and you can change the rules.

WP-CLI and REST

Read any post's audit trail from a script or the command line. Scripted publishes are never blocked.

Modules you can switch off

One settings screen turns each module on or off. Nothing loads that you did not ask for.

Editorial calendar

See the week before it happens

Every scheduled story and every draft on one calendar. Drag a story to a new day and the date changes with it. Drafts with no date wait in a side panel until you place them, and a post never appears in both places at once.

  • Week and month views, up to 12 weeks at a time
  • Filter by status or post type, remembered per user
  • Subscribe from Apple Calendar or Google Calendar

Audit trail

Know who changed what, and how

Every status change and date move is recorded with who made it and which path it came through: the editor, the calendar, WP-CLI or a scheduled publish. When someone asks why a story went live early, the answer is one click away.

  • Read it in the post editor, over REST or with WP-CLI
  • Stored in your own database, next to the post
  • Records changes from every path, including scripts

Getting started

Set up in about five minutes

  1. Install

    Download the zip from GitHub and upload it under Plugins, Add New Plugin. Activate it like any other plugin.

  2. Choose your modules

    Open Editloft in the admin menu and switch on the calendar, the audit trail and the status rules you want. Each is independent.

  3. Work as usual

    Writers keep using the editor. Editors get the calendar and the rules. Nobody has to learn a new workflow.

Questions

Frequently asked questions

Is Editloft really free?

Yes. It is licensed GPLv2 or later, the same license as Edit Flow. There is no paid tier, no licence key and no upsell inside the plugin.

Is it a replacement for Edit Flow?

For some teams. Editloft keeps the calendar and adds an audit trail and role-based status rules. It does not include custom post statuses, editorial comments, editorial metadata, notifications or a story budget. The comparison page lays out exactly what each one does.

What does it need to run?

WordPress 6.4 or newer and PHP 7.4 or newer. It works with the block editor and does not need any other plugin.

Does it send my data anywhere?

No. The plugin code makes no outbound requests and includes no analytics. The audit trail is stored in your own WordPress database. The privacy page has the detail.

Can I turn parts of it off?

Yes. Each module can be switched on or off from one settings screen, and the status rules can be changed with a single filter if your team works differently.

Who maintains it?

One person, in the open. I use Editloft on my own sites and keep it working because I rely on it. It is not a supported commercial product, so I cannot promise a response time, but I read every issue.
