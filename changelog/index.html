Changelog

Release history, dated

Every release is tagged and dated. Here are the recent ones in plain language. The complete technical changelog lives in the repository.

Full changelog on GitHubDownload

Versions

What changed and why it mattered

Versions use the scheme 0.6DDD.HHMM, where DDD is the day of the year and HHMM is the build time.

  • 0.6263.18542026-09-20

    Publishing from an editor account works again

    Editors and administrators can move a post from draft to published or scheduled without a 403 in the block editor. WP-CLI and scheduled publishes are no longer gated. A new wp editloft audit <post_id> command prints a post's audit trail, and a 22-test PHPUnit suite now runs in CI. The calendar feed link is signed with HMAC-SHA256.

  • 0.6218.10492026-08-06

    Saving from the block editor works again

    A REST filter registered without declaring its second argument ended every block-editor save in a fatal error. Quick Edit was unaffected, which made the bug look selective. It shipped in two earlier builds, so anyone on 0.6194.1016 or 0.6199.0938 should update.

  • 0.6199.09382026-07-18

    Calendar entries show their post type icon

    The calendar grid now draws the icon each post type registered, so a page, a post and a custom type no longer look alike. Dashicons take the colour of the entry they sit in so they stay readable against every status.

  • 0.6194.10162026-07-13

    First public release as a standalone fork

    The unscheduled panel began listing only truly unscheduled posts, and the inbound Cloud Sync webhook that could never fire was disabled. The README and changelog were added.

A note on retired modules

On 2026-09-20 I retired the custom status, editorial comments, editorial metadata, notifications, dashboard and Cloud Sync modules to a legacy folder. They are not loaded and are left out of release downloads. Nobody had put real content behind them on the site that uses Editloft, and unused code is a maintenance and security cost. The rules that used to live in the status module now live in a small standalone Status Transitions module.
