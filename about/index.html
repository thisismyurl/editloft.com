Why Editloft exists

Editloft did not start from a blank page. It started from Edit Flow, a plugin that got editorial WordPress right long before I touched it. This is what it did, why I forked it, and what I kept.

By Christopher Ross. Last updated September 20, 2026.

Edit Flow’s history

Edit Flow was built by Automattic, Mohammad Jangda and Daniel Bachhuber, with a copyright span of 2009 to 2019. It was one of the first plugins to treat WordPress as a tool for a team instead of a single writer. It gave WordPress custom post statuses, an editorial calendar, a story budget view and private editorial comments. If you ran an editorial team on WordPress in the 2010s, there is a good chance you ran it on Edit Flow. The ideas held up, and everything Editloft does is downstream of them.

Why it stalled

Edit Flow was written for the WordPress of its time, and that WordPress had a different editor. When the block editor arrived in 2018 the ground shifted under every plugin. Code written against the old editor did not vanish, but it aged, the way a house wired in the 1970s still stands and still needs rethinking before you add a modern kitchen. That is a fact of platform change, not a failing of the people who wrote it. I ran newsroom-style publishing on WordPress for years and Edit Flow was the tool I trusted. When I stopped finding it maintained for my needs, I built the version I needed.

What rebuilt means

Keep the editorial discipline, rewrite the machinery. The plumbing is written for the platform that exists now: the block editor, Full Site Editing and a current PHP baseline. Editloft requires WordPress 6.4 or newer and PHP 7.4 or newer.

Where Editloft is today

Editloft has been through a hard edit. Its first release carried custom statuses, editorial comments, editorial metadata, notifications, a dashboard widget and Cloud Sync. On 2026-09-20 I retired all of them, because none had any real content behind it on my own sites. What remains is what I use every day: an editorial calendar, an audit trail of every status change and date move, and role-based status transitions, with a settings screen to switch each on or off.

I would rather tell you what is missing than imply a completeness that is not there. There is no story budget, no custom statuses, no editorial comments and no notifications. Modules can come back one at a time if there is a real need, and you can watch that happen in the open. The comparison page covers the detail.

Who is building it

I am Christopher Ross. I have been building for the web since 1996 and working in WordPress since 2007, so I was around for the platform Edit Flow was written for and for the shift that left it behind. Editloft is a personal project. I use it in production on my own sites and keep it working because I rely on it. It is not a supported commercial product, so I cannot promise a response time, but I read every issue and pull request.

Read the code

Editloft is on GitHub at github.com/thisismyurl/editloft, licensed GPLv2 or later. The plugin header keeps the original Edit Flow copyright from Mohammad Jangda, Daniel Bachhuber and Automattic, with portions copyright 2024 to 2026 Christopher Ross. The lineage stays visible on purpose. That is how the GPL is meant to work, and it is the reason any of this was possible.
