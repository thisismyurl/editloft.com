Common questions

Frequently asked questions

Is Editloft a fork of Edit Flow?

Yes. It is a maintained fork of the editorial plugin built by Automattic, Mohammad Jangda and Daniel Bachhuber. It keeps the editorial ideas and rebuilds the code underneath for modern WordPress. The original copyright line stays in the plugin header, which is how forking under the GPL is meant to work.

What modules does it have?

Three: an editorial calendar, an audit trail, and status transitions, plus a settings screen that switches each on or off. Custom statuses, editorial comments, editorial metadata, notifications, the dashboard widget and Cloud Sync were retired on 2026-09-20. There is no story budget.

What WordPress version does it need?

WordPress 6.4 or newer and PHP 7.4 or newer.

Is Editloft free?

Yes. It is free to use and to read, licensed GPLv2 or later, and the source is public on GitHub.

Can I run it alongside Edit Flow?

Better not to. The two overlap on calendars and status handling, so pick one.

Why did a publish from an editor account fail?

That was a bug in earlier builds, fixed in 0.6263.1854. Editors and administrators can now move a draft to published or scheduled. Update to the current release.

Why does WP-CLI publish behave differently?

WP-CLI and scheduled publishes are never gated by the status rules, because there is no editor to route them through. They are still recorded in the audit trail.

Coming from Edit Flow

There is no automated migration or import tool. Editloft does not use custom post statuses, editorial comments or editorial metadata, so there is nothing of those to import. Set up the modules you want under Editloft in the admin menu, and read the comparison first to see what you would give up. If you want to talk a move through, the options below are open.

Reporting a bug or requesting a feature

Bug reports and feature requests live on the GitHub issue tracker. A good issue saves a round of back and forth, so please include:

  • What you did, in order, before the problem showed up
  • What you expected to happen
  • What happened instead, with any error message word for word
  • Your versions of WordPress, PHP and Editloft (Tools, Site Health, Info, and the Plugins screen)

You do not have to write it up perfectly. Clear beats polished.

Never used GitHub?

GitHub is the public home where Editloft's code lives and where its to-do list is kept. That list is the issues page, and adding to it is how you tell me something is broken or missing. You need a free account. Open the issues page, select New issue, give it a short title and describe what happened in plain words. Something like "I dragged a story and it disappeared from the calendar" is a genuinely useful report.

Prefer not to use GitHub? Reach me through the Editloft page on my own site. It reaches the same person.

Editloft is maintained by one person. I read what comes in, but I cannot promise a response time.
