Support

Editloft support

Editloft is built in the open, so the best place to ask a question, report a problem, or request a feature is where the code lives. If GitHub is unfamiliar territory, there is a gentler front door too. Both are below.

Common questions

Frequently asked questions

Is Editloft a fork of Edit Flow?

Yes. Editloft is a maintained fork of Edit Flow, the editorial plugin built by Automattic, Mohammad Jangda, and Daniel Bachhuber. It keeps Edit Flow’s editorial ideas and rebuilds the code underneath for modern WordPress. The original copyright line still rides along in the plugin header, which is how forking under the GPL is supposed to work.

Does Editloft have a story budget module?

No, not yet. Edit Flow had one; Editloft does not have it today. The modules that exist right now are custom post statuses, editorial comments, the editorial calendar, editorial metadata, notifications, the dashboard, an audit trail, and settings. I am adding modules one at a time, in the open, and I would rather be straight about what is missing than imply a completeness that is not there.

What WordPress version does it require?

WordPress 6.4 or newer, and PHP 7.4 or newer.

Is Editloft free?

Yes. It is free to use and free to read, licensed under the GNU General Public License version 2 or later (GPLv2). The source is public on GitHub.

Can I run Editloft and Edit Flow at the same time?

Better not to. The two plugins manage a lot of the same things, custom statuses and editorial data among them, so running both at once means two tools reaching for the same wheel. Pick one. Run Editloft or run Edit Flow, not both together.

Coming from Edit Flow

Migrating from Edit Flow

Here is the honest state of things: there is no automated migration or import tool today. If you are moving from Edit Flow, expect to set up your statuses and workflow in Editloft rather than importing them with one click. For many teams that is a short job, because the statuses you want are the ones you already know.

A written migration guide is planned, and it will walk through the move step by step. Until it lands, I would rather tell you the tool does not exist than let you find that out mid-migration. If you are planning a move and want to talk it through, the reach-out options below are open.

Bugs and features

Reporting a bug or requesting a feature

Editloft’s bug reports and feature requests all live in one place: the GitHub issue tracker at github.com/thisismyurl/editloft/issues.

To file an issue, open that page and select New issue. A good issue saves everyone a round of back-and-forth, so it helps to include:

  • What you did: the steps you took, in order, before the problem showed up.
  • What you expected to happen.
  • What actually happened, including any error message word for word.
  • Your versions: WordPress, PHP, and Editloft. All three appear under Tools, then Site Health, then Info, and the Editloft version is on the Plugins screen.

You do not have to write it up perfectly. Clear beats polished. The more of the above you can include, the faster I can see what you are seeing.

Never used GitHub?

New to GitHub, and finding it intimidating?

If you have never used GitHub, it can look like a wall of code meant for other people. It is not as closed off as it looks. GitHub is simply the public home where Editloft’s code lives and where its to-do list is kept. That to-do list is the issues page, and adding to it is how you tell me something is broken or missing.

To file an issue there, you will need a free GitHub account. Once you have one, open github.com/thisismyurl/editloft/issues, select New issue, give it a short title, and describe what happened in plain words. You do not need any technical language. “I clicked Ready and my post disappeared from the calendar” is a genuinely useful bug report.

Prefer not to use GitHub?

You do not have to. You can reach me through my own site instead, at the download and story page for Editloft: thisismyurl.com/downloads/editloft/. That is a softer front door, and it reaches the same person.
