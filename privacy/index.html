Privacy policy

The short version: Editloft runs on your own server and keeps your editorial data there. This page explains what this website and the plugin do and do not collect.

What this website collects

editloft.com is a set of static pages. It sets no cookies, runs no advertising and includes no third-party tracking scripts. It is hosted on Cloudflare Pages, and Cloudflare processes standard request information such as your IP address and browser type to deliver the pages and protect the site, as described in Cloudflare's own privacy policy. We do not tie anything you do on this website back to you.

What the Editloft plugin collects

Editloft runs inside your WordPress site. The audit trail it records, meaning who changed a post's status or date and through which path, is stored in your own WordPress database as post meta and stays there. The calendar stores each user's filter preferences as user meta. Editloft includes no analytics and no usage tracking.

As of version 0.6263.1854, the plugin code makes no outbound requests, so it does not send your content or your editorial data to me or to any third party. Earlier builds included an optional Cloud Sync module, off by default. It was retired on 2026-09-20 and is not part of the plugin.

The calendar feed

If you turn on the optional calendar feed, anyone who has the signed feed link can read the titles and dates it lists. Treat the link like a password. You can regenerate the secret from the calendar settings, which stops every old link from working. The feed is off by default.

Downloads and third parties

The plugin is downloaded from GitHub, which has its own privacy policy. This website is hosted on Cloudflare, which has its own. No other third party is involved in running this site or the plugin.

Contact

Questions about privacy, or about what a feature does with data, are welcome on the support page or the GitHub issue tracker. If this policy changes, the updated version will be posted here.
