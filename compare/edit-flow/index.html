Choosing

Which one fits your desk

Choose Editloft if

  • You want the calendar, a history of changes and publishing rules, and nothing else
  • You care about a small plugin that loads only what you turn on
  • You work in the block editor and want a plugin built for it
  • You want to script or audit editorial history

Stay with Edit Flow if

  • Your process depends on custom post statuses such as Pitch or Needs review
  • You rely on private editorial comments or editorial metadata
  • You need email notifications on status changes or a story budget view

Questions

Moving between them

Can I run Editloft and Edit Flow together?

It is better not to. They overlap on calendars and status handling, so running both means two tools reaching for the same controls. Pick one.

Is there a migration tool?

Not yet. Moving from Edit Flow means setting up Editloft's modules and rules rather than importing. Editloft does not use custom post statuses, so there are none to carry across.

Why fork instead of contributing upstream?

I did both. The fork exists because I wanted a much smaller plugin than the original, and I contributed small security fixes to Edit Flow while auditing it. The GPL and the original copyright line make that possible.

The full story of the fork is on the about page.
